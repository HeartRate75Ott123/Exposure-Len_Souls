# 特效重构方案：空间扭曲场 / 时空回溯 / 夺魂索命 / 引力枪磁力线

> 状态：**已按确认结论实现（1.7.51）**。日期 2026-10。前置：冻结天穹（`TimeFreezeSky`）已实机验证的
> "AFTER_LEVEL 全屏 pass + 深度掩码" 路径，本方案的大量屏幕特效复用同一条路径。

---

## 0. 共用底座（新增，服务于全部四项）

### 0.1 `client/fx/ScreenFxManager` —— 统一屏幕后处理

一个单例时间线，容纳任意条"瞬时屏幕特效"，每帧合成成**一次**全屏 quad：

| 特效 | 参数 | 用途 |
|------|------|------|
| `WARP` | 强度 0..1、中心点、方向、拉丝指数 | 时空回溯的隧道拉伸 |
| `CHROMA` | 像素偏移 0..1 | 拉伸/穿梭时的色散 |
| `STREAK` | 强度、速度 | 径向速度线（穿梭感） |
| `FLASH` | 颜色 + 强度 0..1 | 白闪/绿闪/破防闪 |
| `TINT` | 颜色 + 强度 + 脉冲频率 | 绿色魂雾暗角、冰蓝暗角 |
| `RIPPLE` | 屏幕中心、半径、强度 | 从某点扩散的圆环 |

- 实现：`ScreenFxManager.push(Fx spec)`；每 tick 推进进度，`afterLevel` 时若有活动特效 →
  把主帧缓冲**颜色 blit 到常驻 `TextureTarget`**（避免自采样 UB，尺寸变化重建）→ 跑 `screen_fx` 着色器 → 结束。
- 着色器：`assets/lensouls/shaders/core/screen_fx.{json,fsh,vsh}`（一张，uniform 驱动全部子效果）。
- 挂钩：`RenderLevelStageEvent.AFTER_LEVEL`（与 `TimeFreezeSky` 同一个位置：Iris 合成之后、清深度之前）。
  深度测试关闭、只写颜色 → 不影响地形遮挡判断，也不染色 HUD（HUD 在其后）。
- Iris：走"自定义 `ShaderInstance` + 主帧缓冲直绘"，此刻 `IrisRenderingPipeline.isRenderingWorld == false`，
  不会被抢回 gbuffer FBO（冻结天穹已实测）。

### 0.2 `client/fx/WorldFx` —— 世界空间发光带/环

- `WorldFxRenderTypes`：两个参数化 RenderType
  - `ribbon(shader, additive, throughWall)`：`TRIANGLE_STRIP`，`POSITION_TEX`（UV0.x = 沿线 0..1，UV0.y = 横向 0..1）
  - `ring(shader, additive)`：平面环（QUADS 带）
- 两个核心着色器：
  - `fx_ribbon`：沿线的能量流（`fract(uv.x - t*speed)` 亮包）、边缘软衰减、白芯、可按 uniform 上色
  - `fx_ring`：环面径向渐变 + 旋转缺口 + 加色
- 全部经 `MultiBufferSource`（Iris 会分到正确阶段），输出 `MAIN_TARGET`。

### 0.3 `client/fx/ScreenProjector` —— 世界点 → 屏幕坐标

供"从目标位置扩散的屏幕涟漪"用：`Matrix4f` 投影 + `Camera` 反算 NDC，越界则丢弃。
（避免为每个特效单独写 mixin，纯数学即可。）

### 0.4 服务端 `fx/FxScheduler`

`ServerTickEvent.Post` 驱动的延迟任务队列（`schedule(delayTicks, Runnable)`），
用于"前摇播完再传送"的时序。只保存短生命周期任务，玩家登出即清。

## 1. 空间扭曲：操作场（球）→ 金色电流场

**现状**（`SpatialWarpOutlineRenderer` + `WireframeRenderTypes`）：
16 经 × 8 纬的 `RenderType.LINES` 线框，颜色写死"上黄下橙"，线宽 2px，`COLOR_DEPTH_WRITE`，
无动画、无辉光、不透明、`lensouls_lines_main` 只有这一个用途。

**重构**：

1. **几何从线换成带状 ribbon**（`POSITION_TEX`，每条经线/纬线一段 strip）
   - 带宽 ≈ 半径 × 0.012，UV0.x 沿线、UV0.y 横向 → 边缘由着色器做软衰减，天然抗锯齿
   - 顶点量：16 经 × 24 段 + 7 纬 × 32 段 ≈ 1.4k 顶点（比现在更省）
2. **双球**
   - 外层：`Attributes.BLOCK_INTERACTION_RANGE`（方块交互）—— 16 经 × 8 纬，主金色
   - 内层：`Attributes.ENTITY_INTERACTION_RANGE`（实体交互）—— 8 经 × 4 纬，偏青金、透明度 45%
   - 同心（照片拍摄坐标）；两球都在 `AFTER_ENTITIES` 一次批次内绘制
3. **`warp_field` 着色器**
   - 基础：金黄 `#FFCF5A` → 橙金 `#FF9A2E` 的球面渐变（上亮下暗），赤道处最亮
   - **电流**：两条不同速度/相位的亮包沿 UV0.x 跑（`0.35/s`、`0.55/s`），叠加
     `fbm(uv * 40 + time)` 抖动做出"电弧跳变"，`pow(x, 4)` 锐化成白芯
   - **间歇放电**：`step(0.72, hash13(floor(uv.x*segments), floor(t*3)))` 决定某段是否亮，
     避免整球均匀发光的"塑料感"
   - **节点**：两极 + 4 个赤道方位点各放一个小亮球 + 6 条放射短线（同一 ribbon 批次，短段）
   - 加色混合、`COLOR_WRITE`（不写深度）、距离 > 24 格淡出、视线正对时略降（防糊屏）
4. **脉冲扫描**：每 1.4s 一圈"经纬扫描波"从赤道向两极扩散（`sin(r - t)` 沿球面）
5. **球心宝石**：十字星 + 缓慢旋转的 3 个正交细环（`fx_ring`）
6. **进入反馈**：玩家进入/离开球体时，整球亮度阶跃一档（`ClientTickEvent` 内检测距离）

**不动**：交互范围语义、`SpatialWarpActivatePacket`、球心数据来源（`ClientAbilityCache`）。

## 2. 时空回溯：短暂拉伸穿梭

**现状**：`TemporalSnapshot.apply` 里直接 `player.teleportTo(...)`（可能跨维度），
客户端**零视觉、零音效**——玩家看到的是瞬间跳变。触发点两处：被动致命伤（`TemporalRecallHandler.onLivingDamagePre`）
与主动 C2S（`TemporalRecallTriggerPacket`）。

**方案（两段式，带前摇）**：

1. 服务端（`TemporalRecallHandler` / `TemporalRecallTriggerPacket` 共用新方法 `beginRecall(player, snapshot, cause)`）
   - `FxScheduler.schedule(RECALL_DELAY_TICKS=6, () -> snapshot.apply(player))`
   - 立刻发 `TemporalRecallFxPacket(phase=CHARGE, x/y/z of snapshot, sameDim)`，到达延迟后再发 `phase=ARRIVE`
   - 前摇期间：`Slowness` 0（不减速，只锁位置感）→ **只加 0.3s `Invulnerable`（仅被动路）**，防打断
   - 配置：`Config.TEMPORAL_RECALL_DELAY_TICKS`（默认 6，可设 0 = 关闭前摇，退化成"只有到达特效"）
2. 客户端 `client/fx/TemporalRecallFx`
   - **CHARGE（0.30s）**：`WARP` 0→0.55（UV 向屏幕中心拉）、`STREAK` 0→1、`CHROMA` 0→8px、
     末尾 `FLASH` 白 0.35；玩家周围生成"时间碎屑"粒子（8 个 `SoulWisp` 调白）向身后吸入
   - **ARRIVE（0.45s）**：`WARP` 0.55→0 回弹 + 衰减振荡（`exp(-t*6)*cos(t*18)`）、
     `RIPPLE` 从屏幕中心扩散、`CHROMA` 8→0、`FLASH` 白 0.5→0；
     世界空间：脚下 3 圈青色 `fx_ring`（错峰 0.06s）+ 12 缕上升的时间尘埃
   - 音效：新增 `temporal_recall`（若有素材）；无素材则用 `SoundEvents.ENDERMAN_TELEPORT` 变调 + `AMETHYST_BLOCK_CHIME`
3. 视觉语义：**"被时间的潮水拖回去"**——先向内塌缩（前摇），再在落点炸开（到达），中间那一下瞬移被白闪盖住。

**风险**：0.3s 前摇是玩法改动（尤其主动触发的手感）；`RECALL_DELAY_TICKS` 必须可配。
跨维度传送时客户端会经历一次 `respawn` 式的 level 切换 → 到达特效需在 `ClientLevel` 变更后重新挂载
（`ClientPlayerNetworkEvent`/`level == null` 时丢弃）。

## 3. 夺魂索命：绿色魂魄

**现状**（`SoulSeverHandler.spawnShockwave`）：3 圈原版 `SWEEP_ATTACK`（橙白暴击弧）+ 8 层
`ENCHANTED_HIT`（白附魔光点）+ `EXPLOSION_EMITTER`（爆炸烟雾）——与"夺魂"语义完全不符，且不可控。

**方案**：

1. 服务端：新增 S2C `SoulSeverFxPacket(targetId, success, ratio)`
   - 成功/失败都发（失败播"索命被挡"的暗绿短闪）
   - 删除原 `SWEEP_ATTACK` / `ENCHANTED_HIT` / `EXPLOSION_EMITTER`，只保留少量 `ParticleTypes.SOUL`（如有）
2. 新增粒子 `SoulWispParticle`（`ModParticleTypes.SOUL_WISP` + 自定义 provider）
   - 外观：复用 `particle/flying_spark` 贴图或新画 8×8 柔光点，加色混合
   - 运动：从目标躯干随机点升起，`vy = 0.06`，水平螺旋（`sin/cos` 相位）+ 逐渐朝玩家方向加速
   - 生命：0.9~1.5s（`lifetime` 随机），颜色 `#7CFFB2 → #2FE08A`，末端拖尾 3 个残影点
   - 成功 18 缕、失败 6 缕（更暗、更快熄灭）
3. 世界空间
   - `fx_ring`：目标脚下 3 圈绿色环从下往上收缩（0.5s），模拟"魂魄被抽离"
   - `fx_ribbon`：成功时 6~8 条绿色细丝从胸口向外爆开（0.35s 消失）
   - 目标身上：**绿色 glint** 0.6s（复用 `StatusGlintBufferSource`，新增 `SOUL_SEVER` 状态）
4. 屏幕空间：`TINT` 绿色暗角脉冲（0.35s、强度 0.22）+ 从目标屏幕位置扩散的 `RIPPLE`（很弱）
5. 音效：沿用 `TRIDENT_THUNDER`，叠加一个新的"吸气"音（`AMETHYST_BLOCK_RESONATE` 变调或自定义）

**风险**：绿色 glint 涉及现有三态互斥（`STUNNED红 > FROZEN蓝 > INVINCIBLE白`），需插一档
`SOUL_SEVER绿`（建议优先级：STUNNED > SOUL_SEVER > FROZEN > INVINCIBLE），并保证不改动冻结/破韧表现。

## 4. 引力枪：磁力线

**现状**（`GravityTetherRenderer` + `GravityTetherRenderTypes`）：12 段正弦叠加偏移的单条白色 ribbon
（`rendertype_lightning`），平直、单色、无脉冲、无辉光、端点无反馈。

**方案**：

1. **三股编织**：主线 + 两条副线（振幅 0.55 / 0.30，频率相位不同），
   两端权重按 `sin(πt)^0.6` 收敛 → 三股在源点/目标点汇聚成束；三条共用一套偏移基，避免"面条乱飘"
2. **螺旋**：偏移向量绕路径轴旋转（`helixRot = t*2.2 + time*0.8`），任意视角看都是立体缠绕
3. **`fx_tether` 着色器**（替换 `rendertype_lightning`，改为 `POSITION_TEX` ribbon）
   - 青白渐变 `#BFE9FF → #5FB6FF`，靠端点更亮
   - 沿 UV0.x 的两个能量脉冲（速度 0.9 / 1.7），`pow` 锐化白芯
   - 横向软衰减 + 外辉光（第二 pass：宽 0.10、alpha 0.25、加色）
   - 弱抖动：`fbm(uv.x*8 + time*3)` 轻微横向扰动，模拟磁场不稳定
4. **端点**
   - 目标身上："磁笼"3 个正交细环（`fx_ring`），反向缓慢旋转，0.5s 淡出
   - 枪口/玩家手部：小十字星 + 一次性 `FLASH` 极弱蓝闪
5. **粒子**：每 tick 从目标向玩家方向发射 2 个被吸引的尘埃（`FlyingSparkParticle` 调蓝、速度继承、寿命 0.5s），
   强化"被吸过来"的方向感
6. **受伤反馈**：保留延迟平滑 `POS_DELAY`；受伤时改为"频率更高、幅度更小"的抖动（现在只是加倍延迟）
7. **距离衰减**：> 32 格磁力线渐隐（与射程语义一致）

## 6. 技术约束与风险

| 项 | 结论 |
|---|---|
| Iris 屏幕特效 | 走 `AFTER_LEVEL` + 主帧缓冲直绘（冻结天穹已验证）；不采样 shaderpack 纹理 |
| Iris 世界几何 | 必须走 `MultiBufferSource` + RenderType；`MAIN_TARGET` 输出；不裸调 GL |
| 颜色自采样 | 屏幕 FX 需要主画面颜色 → `glBlitFramebuffer` 到常驻 `TextureTarget`；尺寸变化重建 |
| 手部 | 屏幕 FX 在 `AFTER_LEVEL`，手部之后渲染 → 不受拉伸影响（可接受；若要包含手部需换钩子，风险高，先不做） |
| 回溯前摇 | 玩法改动，必须可配；跨维度时需在到达后重新挂载特效 |
| 绿色 glint | 需梳理 `StatusGlintBufferSource` 状态优先级，不能影响冻结/破韧 |
| 性能 | +3 张 core shader（`screen_fx` / `fx_ribbon` / `fx_tether`）+ `fx_ring` 可复用 `fx_ribbon`；
  世界几何总量 ≈ 3k 顶点；屏幕 FX 仅在有特效时执行一次全屏 pass（含一次 blit） |

## 8. 落地记录（1.7.51）

### 三条确认结论的落法

1. **时空回溯要 0.3s 前摇** —— `Config.temporalRecallDelayTicks`（默认 6 tick）。
   服务端 `TemporalRecallHandler.beginRecall` 先发 `TemporalRecallFxPacket(CHARGE)`，
   `FxScheduler` 到点后真正 `apply` 并补发 `ARRIVE`；被动保命与主动触发共用同一入口
   （`TemporalRecallTriggerPacket` 原来自带的背包扫描已删除，改走 `consumeTemporalPhoto`）。
2. **不做绿色 glint，改为着色器版"魂飞魄散"** —— 命中成功后由 `SoulSeverFxPacket` 触发：
   18 缕绿色魂火粒子（`soul_wisp`）+ 3 圈上升收缩绿环 + 6 条螺旋魂丝（`fx_soul_green`）
   + 屏幕绿色暗角脉冲与从目标扩散的绿环（`ScreenFxManager`）。
   原版 `SWEEP_ATTACK` / `ENCHANTED_HIT` / `EXPLOSION_EMITTER` 全部删除。
3. **空间扭曲只保留一层球** —— 半径仍是方块交互距离；几何仍是经纬网格（16×20 经 + 7 纬环），
   但每条线换成细缎带，由 `fx_warp_gold` 叠金黄色电流（柔边 + 奔跑亮包 + 闪烁 + 白芯）。
   另外加了：两极/赤道六方位电弧节点、两条缓慢转动的斜环、**玩家进入球内时整体亮 1.35 倍**
   （正是为了方便观察内部）。

## 9. 实机反馈修正（1.7.52）

### 9.1 无光影（vanilla）下的问题定位

截图里那些**向上飘散的绿色方块**不是设计，是粒子踩坑：
`SoulWispParticle` 一开始复用了 `flying_spark` 贴图 + `PARTICLE_SHEET_LIT`（alpha 测试）。
alpha 测试是"硬切"，把柔光点切成了**硬边方片**；再把 `quadSize` 放大到 0.05~0.11 格，
近看就是一块块绿方块。

- `quadSize` 收小到 0.045~0.08；
- 数量提升（成功 34 缕 + 14 缕魂核爆散），保证"更明显"的同时不再是方片。

### 9.2 Iris 不兼容的根因（空间扭曲 / 磁力线 / 魂火环）

把"沿线电流脉冲"改成**逐顶点在 CPU 算好写进颜色**（几何本就每帧重建），柔边用**多层叠加**
（白芯 / 中晕 / 外辉光）近似。删除 `fx_ribbon` 着色器与 3 份 json。

顺带按需求：**引力枪不再发射末地烛粒子**，只保留电弧本身。

### 9.3 时空回溯的位置改为"按快门那一刻"

暗房冲洗/手上拍立得都会让落点变成"出片时站的地方"。
现与空间扭曲同源：`PhotoInjectionHandler.onFrameAdded`（拍照瞬间）按 exposureId 缓存完整快照
（维度/坐标/朝向/生命/饥饿），出片时 `pollTemporalSnapshot` 取用；
缓存缺失时还能用帧自带的 `POSITION / YAW / PITCH / DIMENSION` 兜底重建。

## 10. 第二轮实机反馈修正（1.7.53）

### 10.1 "不自然的缺口 / 尖刺"的真正原因（金色场 + 磁力线）

三条原因叠在一起：

1. **带宽方向在相邻线段之间翻转**：`polyline` 原来用"切线 × 世界上方"求宽度方向，
   当切线接近竖直时会切到另一根参考轴，相邻段方向翻面 → 四边形被拧成尖刺。
   现在固定挑"与切线最不平行的世界轴"做参考，并对退化段（长度 ≈ 0）直接跳过。
2. **用"多层加宽叠加"假装柔边**：上一版为了在没有柔边的情况下发光，把最外层拉到
   3.6× 宽 —— 在球面两极附近层与层自己穿插，遮出一块块缺口。
   现在柔边重新交给着色器（UV 横截面衰减），几何只有**一层细缎带**。
3. **一个 4096 字节的 batch 塞三个特效**：顶点量一大就可能截断，表现为"少了一截"。
   现在每个特效各自 `begin/flush`，互不影响。

顺带加了两重保险：`NaN/Inf` 顶点直接丢弃；所有向量归一化前先查长度。

### 10.2 Iris：不引入 Photon，改用"绘制时机"

`fx_ribbon` 自定义着色器的柔边/脉冲/生长全部保留了，Iris 兼容不靠换着色器，而靠**时机**：
Iris 只在"世界渲染进行中"把未知着色器抢到 gbuffer；而
`LevelRenderer.renderLevel` 返回之后（`finalizeLevelRendering` 已跑完，
`isRenderingWorld == false`）它就不再干预。于是把整条世界特效搬到
**`AFTER_LEVEL` 手动绘制**（`client/fx/WorldFxPass`）：

- 投影/视图矩阵取自事件（相机相对坐标 + 场景深度），`GL_LEQUAL` 深度测试 → 地形照常遮挡，不写深度；
- 每个特效单独设 uniform（脉冲速度/锐度/生长/消散/透明度）再 flush，
  一张 `fx_ribbon` 承担金色电流、磁力线、魂丝三种风格；
- 代价与冻结天穹一致：不经过 shaderpack 的后处理。

> 为什么没有按建议引入 Photon 作前置：Photon 的做法是把粒子/特效**合成进 Iris 的 gbuffer**
> （自带一整套 `IrisFrameTarget` / `GameObject` / 粒子栈），换来 shaderpack 的后处理；
> 那要求我们的特效整体迁到它的框架里，并把 Photon 变成硬前置。
> 现在的 `AFTER_LEVEL` 路线不需要任何新依赖、保留我们自己的着色器，先把"光影下可见 + 好看"两件事同时拿到；
> 若之后想要"特效也吃 shaderpack 的光晕/色调"，再评估迁到 Photon 的 FX 框架。

### 10.3 破碎镜面：片数减少 + 逐渐炸开脱落

- 裂片从 ~11 片/屏宽降到 **~4.5 片/屏宽**；
- 新增 `FxShardPhase`（0..1 碎裂推进）：每片按自身 hash 分先后起爆，
  依次**向外飞出 + 缩小**，贴边露出**深蓝黑"时间裂隙"**与细亮裂纹（彩虹只在裂纹上薄薄一层）；
- 前摇里 phase 由 0 推到 1（先裂后碎），落点时 phase=1（已全碎）再随强度一起回落。

### 10.4 夺魂索命：渐入 → 推进 → 散开

- **进**：魂丝沿路径生长（`FxGrow` 0→1，0.3s 从体内抽出）；
- **推**：7 个环**错峰连续推出**（每个环有自己的起爆时刻，半径逐环变大、向上抬升）；
- **出**：最后 45% 里 `FxTaper` 0→1 —— 末端**变细**，同时半径/螺旋角**外扩散开**，
  配合整体 alpha 衰减；魂柱同步收缩。

## 12. 第四轮实机反馈修正（1.7.55）

### 12.1 引力枪：帧率无关的延迟平滑（消顿挫）

原来的 `POS_DELAY` 是"每帧 lerp 0.06"——帧率越高追得越快、越低越黏，而且端点直接用

## 13. 第五轮实机反馈修正（1.7.56）

### 13.1 磁力线"不连续感"：查到三个来源，全修

截图里那道断续/亮斑的束，成因不是单一的：

1. **带宽方向的"扭面"**（主因）：旧 `polyline` 每段都重新挑一根"最不平行的世界轴"当参考，
   参考轴在相邻段之间会突变 → 四边形被拧 90°，加色叠加后表现为一段段亮斑/断口。
   现改为**平行传输**：用第一段的方向建初值，之后把上一段的方向投影到新切线的法平面再归一化，
   整条缎带扭转连续。
2. **副线与主线交叉时亮度翻倍**：三股螺旋必然相交，相交处 additive 会把亮度叠成白色块。

3. **与地形/水面共面时的深度断续**（"穿模感"）：`AFTER_LEVEL` 用的是场景深度，
   贴着方块面走时 `LEQUAL` 会一半过一半不过 → 虚线。
   现在整条世界特效开启 `glPolygonOffset(-1, -2)`，深度比较上"拉近"一点，共面不再撕裂。

### 13.2 时空回溯：可控的分段退化，窗口拉长

## 15. 第七轮实机反馈修正（1.7.58）：缩放的"收回"改成阻尼弹簧

**现象**：特效收回那一下缩放没有平滑弹回，反而像卡一下。

**原因**：落点段的缩放用的是
`warp = 衰减 × (1 + 0.45·sin(2.2πu))` —— 正弦"回弹"会**来回抽动**
（1 → 1.45 → 0.55 → 1 → …），末端再被总开关压掉，观感就是"先抽两下再突然定住"。

**改法**：

1. 换成**临界阻尼弹簧**：`springBack(u) = (1 + ωu)·e^(−ωu)`，ω = 4.4。
   起手最快、之后单调收敛到 0，**没有过冲** —— 正好是"被拉回原位"的观感；
2. 总开关提前到 **0.97** 收干净（`1 − smoothstep(0.62, 0.97, u)`），
   最后 3%（≈45ms）完全是普通画面，避免"收回那一帧"跳一下；
3. 前摇结尾的裂片强度与落点起点对齐（1.05 → 0.95），CHARGE→ARRIVE 不再有小跳。

实测曲线（u = 落点段进度）：

| u | 0.00 | 0.20 | 0.40 | 0.60 | 0.80 | 0.95 | 1.00 |
|---|---|---|---|---|---|---|---|
| warp | 0.580 | 0.452 | 0.275 | 0.151 | 0.037 | 0.000 | 0.000 |
| shard | 0.950 | 0.950 | 0.885 | 0.390 | 0.002 | 0.000 | 0.000 |

## 16. 第八轮修正（1.7.59）：线条衔接处改用三角带

**现象**：空间扭曲的金色场线在接缝/交叉处有"不自然衔接"。

**根因**：整条线是"一段一个四边形"拼的。相邻两段在接缝处各自用自己的宽度方向
（`rights[i] + rights[i+1]` 归一化后再乘半宽），两者角度略有差异 → 接缝处形成一个**重叠的楔形**；
加色混合下重叠区亮度翻倍，于是线上出现一颗颗亮斑、观感就是"线条不连续/衔接生硬"。

**改法**：全部几何改成 **`TRIANGLE_STRIP`**，接缝处两个顶点由相邻两段**共用**：

- 既没有缝隙（不会透出背景），也没有重叠（不会亮斑），整条线亮度连续；
- 多条带之间用"重复首对顶点"制造退化三角形断开（零面积、不渲染）；
- 圆环用同样的带（末点重复首点闭合，接缝只有一个点，看不见）；
- 带宽方向仍是平行传输，扭转连续。

顺带收益：引力枪磁力线、夺魂索命魂丝同样是带，接缝亮斑一起消失。

## 17. 第九轮修正（1.7.60）：自由缎带改成"朝相机"

**现象**：改完三角带后第三人称磁力线很好，第一人称几乎看不见。

**根因**：缎带是**平面条带**，带宽方向原来用平行传输算。
第一人称下视线基本**沿着光束方向**看，带状平面正好侧对着镜头 → 投影宽度趋近 0，
就成了"看不见的细线"；第三人称是侧看，所以满宽、很好看。

**改法**：没有显式带宽方向的自由缎带（磁力线、魂丝、光柱、落点光柱）一律**朝相机**：
`right = normalize(cross(tangent, -point))`（几何是相机相对坐标，相机在原点），
这等价于绕自身轴的 billboard —— 任何角度都满宽。球面经纬网仍用球面切向（贴在球面上）。

退化保护：切线平行视线时回退到平行传输；算不出的点用相邻点补。

同时把近镜头淡出从 1.0~3.2 格收窄到 **0.5~1.6 格**（billboard 后不需要那么狠，
否则第一人称开头几格是黑的）。

## 18. 第十轮修正（1.7.61）：回溯"离开"过渡重做

上一版虽然把缩放换成了阻尼弹簧，但**退出仍然生硬**——因为两个更根本的问题没解决：

1. **传送那一帧没有盖住**：CHARGE 的白闪只到 ~0.25~0.5，世界在特效中间"啪"地换掉，
   观者看到的是"画面还在抖、地方已经变了"；
2. **碎块在落点段是静止的**：`FxShardPhase` 直接给 1.0（已全碎），退出时只是把整张
   "碎裂图案"整体淡出 —— 那是一层**静态图案的交叉溶解**，不是"碎块飞散"，
   再平滑的曲线也救不了这个观感。

现在的做法：

| 阶段 | 白闪 | 碎块 | 拉伸/色散 |
|---|---|---|---|
| CHARGE 0.50s | 末段 `smoothstep(0.70,1.0)` → **1.0 全白** | 裂到 0.55（只裂开，不散） | 0→0.55，最后被全白吞掉 |
| ARRIVE 1.55s | 1.0 → 0（0.22s 揭开新场景） | 相位 0.55→1.0 **一边向外飞一边淡**，强度 0.30 后开始收，0.88 归零 | 临界阻尼回收 + 各自收尾窗，1.0 归零 |

两段在切换点数值完全对齐（warp 0.55 / shard 0.90 / chroma 0.85 / streak 0.26 /
flash 1.0 / shardPhase 0.55），所以传送前后**没有任何跳变**，
新场景是从"全白 → 碎块飞散 → 世界慢慢稳下来"这三层里长出来的。

## 19. 第十一轮修正（1.7.62）：线段末端的假淡出 + 碎块"滑回原位"

### 19.1 场线"起点全亮、末端淡出"——是个真 bug（不是控制没生效）

`fx_ribbon` 里生长动画的淡出没有加开关：

```glsl
float growFade = 1.0 - smoothstep(FxGrow - 0.08, FxGrow, along);   // 旧
```

`FxGrow` 默认 1.0 → 每根线在 `along` 的最后 8% 被淡到 0，而起点（`along`=0）是满亮：
- 经线 = 从一极到另一极，**末端淡、起始硬**；
- 纬线环 = 首尾相接，接缝处正好"淡出端接上满亮端" → 就是你看到的那种硬接。

现在只有**正在生长**（`FxGrow < 1`）时才做裁切与末端淡出，静态线整条均匀，
闭合环首尾亮度一致，接缝消失。

### 19.2 玻璃错位"平滑撤走"：新增 `FxShardRestore`

以前退出只把碎块的**强度**淡掉，错位偏移始终停在最大值——等于把一张碎玻璃图案
整体做交叉溶解，当然不像"撤走"。现在：

- 新增 uniform `FxShardRestore`（0..1），把**错位偏移、每片缩放、裂缝宽度、裂隙**一起乘 `(1-restore)`；
- 落点段时序：`0~0.30` 碎块继续向外飘一点 → `0.22~0.80` **错位平滑滑回原位**（缝隙合拢）
  → `0.55~0.95` 归位之后再淡掉残余裂纹；
- 实测 restore=0.5 时缝隙明显收窄、碎块位移减半；restore=1.0 时画面回到正常，只剩极淡裂纹再淡出。

### 19.3 已逐项核对"控制确实生效"

| 环节 | 核对结果 |
|---|---|
| `screen_fx.json` uniforms | 含 `FxShard` / `FxShardPhase` / `FxShardRestore`（新） |
| `ScreenFxManager.render` | 每帧上传三个值（`set1f`） |
| `TemporalRecallScreenFx` | CHARGE 段 `restore=0`；ARRIVE 段 `restore = smoothstep(0.22, 0.80, u)` |
| `fx_ribbon.fsh` | 生长淡出已加 `if (FxGrow < 0.999)` 开关 |

> ⚠ 另外提醒：`temporalRecallDelayTicks` 的默认值（6→9）对**已存在**的
> `run/config/lensouls-common.toml` 不生效，要删掉该文件或手动改。

## 21. 第十二轮修正（1.8.48）：时空回溯「椭圆羽化蒙版」

> 需求原话：「优化一下时空回溯特效，加一层带羽化边缘的椭圆蒙版，进入时从四周逐渐覆盖，退出时从中心向四周缓缓褪去」

### 21.1 落点

| 位置 | 改动 |
|---|---|
| `shaders/core/screen_fx.fsh` | 新增 `FxMask` / `FxMaskEdge` / `FxMaskSoft` / `FxMaskRadius` / `FxMaskCenter` 五个 uniform + 一段蒙版合成，位置在**全屏闪光之前、其它所有子效果之后** |
| `shaders/core/screen_fx.json` | 五个 uniform 的默认值必须登记（`ShaderInstance.getUniform` 只认 json 里声明过的条目，GLSL 里声明了但 json 没写 → Java 侧 `set1f` 直接静默失效） |
| `client/fx/ScreenFxManager.java` | `State` 新增 `mask / maskEdge / maskSoft / maskRadiusU/V / maskCenterX/Y` + 渲染时下发 |
| `client/fx/TemporalRecallScreenFx.java` | 两个阶段各自推进前沿；碎块自身淡出窗口从 `0.62~0.96` 延到 `0.72~1.00`，让蒙版推出去时外圈还有东西可看 |
| `tools/temporal_mask_preview.py` | 离屏预览（同公式），产出 `docs/effect_preview_temporal_mask.png` |

### 21.2 公式（一个公式同时表达「四周覆盖」与「中心褪去」）

```glsl
me   = length((uv - FxMaskCenter) / FxMaskRadius);            // 椭圆归一化半径：0=屏心，1=椭圆边界
keep = smoothstep(FxMaskEdge - FxMaskSoft, FxMaskEdge + FxMaskSoft, me);
col  = mix(sceneAt(vUV), col, keep);                           // 圈外退回未处理的原画面
```

- 前沿 `edge` **由大到小收** ⇒ `me` 小于前沿的部分被"保留量"覆盖，视觉上是**四角先亮、逐圈漫向屏心**（进入）；
- 前沿 **由小到大推** ⇒ 屏心先掉回原画面、逐圈向外扩（退出）。
- 不需要"极性"开关：`me ≥ 0` 天然使 `edge ≤ -soft` 时整屏 `keep = 1`、`edge ≥ 1.28` 时整屏 `keep = 0`，
  所以同一条公式只要换推进方向就能表达两种形态。
- 羽化 `soft = 0.16`（椭圆归一化半径单位）≈ 屏幕高度 12% 的过渡带，两端都不会出现硬边。
- **闪光画在蒙版之后**：白场始终整屏，传送那一帧不会因为中心还没盖住而露缝。

### 21.3 时间轴（常量都在 `TemporalRecallScreenFx`）

| 阶段 | 参数 | 值 | 说明 |
|---|---|---|---|
| 进入 | `MASK_ENTER_START → MASK_ENTER_END` | 0.02s → 0.34s | 前沿 `1.28 → -0.24`；收在白闪（`t≈0.35`）之前 |
| 退出 | `MASK_EXIT_START → MASK_EXIT_END` | u 0.00 → 0.95（≈1.47s） | 前沿 `-0.24 → 1.28`，中心先褪、逐圈推到边缘 |
| 形状 | `MASK_RADIUS_U/V` | 0.62 / 0.74 | uv 归一化：宽 > 高 ⇒ 屏幕上是一条横向椭圆 |
| 端点 | `MASK_FAR / MASK_NEAR` | 1.28 / -0.24 | FAR=整屏原画面，NEAR=整屏特效 |

### 21.4 兼容

- `State.mask` 默认 0，其它屏幕特效（夺魂索命 / 削韧冲击 / 拍照）**完全不受影响**（`keep` 恒为 1）。
- 蒙版本身不计入 `State.isEmpty()`：没有子效果时不会为了画蒙版而多跑一趟 pass。
