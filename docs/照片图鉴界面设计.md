## 3. 总体架构

```
出片（PhotoInjector，ABILITY_STEAL 成功）
   └─ PhotoGalleryRecorder.record(player, entityId)      ← 记录首次窃取时间
                         │
玩家数据附件  PhotoGalleryAttachments.PHOTO_GALLERY  (serializable + copyOnDeath)
   stolen:   entityId → 首次窃取 gameTime       （解锁条目 + 排序源）
   favorites: entity:<id> / set:<setId>          （收藏）
   clickRule: GRANT | EQUIP                      （点击规则）
                         │
        S2C PhotoGallerySyncPacket（登录 / 变更后 / 打开界面时）
                         ▼
         客户端 PhotoGalleryClientCache（内存镜像，切世界即清）
                         │
                PhotoGalleryScreen（玻璃面板 + 网格 + 搜索 + 滑钮 + 快捷功能）
                         │
   C2S PhotoGalleryActionPacket / PhotoGalleryShortcutPacket
                         ▼
       服务端权威结算（发照片 / 装照片 / 收藏 / 规则 / 清空 / 去重）
                         │
        PhotoGalleryMenu（41 隐藏背包槽：让发放结果同步回客户端）
```

## 4. 数据层

### 4.1 玩家附件 `PhotoGalleryData`

注册在 `PhotoGalleryAttachments`（写法照 `feather/FeatherAttachments`）：

```java
TYPES.register("photo_gallery",
        () -> AttachmentType.serializable(PhotoGalleryData::new).copyOnDeath().build());
```

| 字段 | 类型 | 语义 |
|---|---|---|
| `stolen` | `Map<String, Long>`（entityId → 首次窃取的 `level.getGameTime()`） | 解锁集合 + 排序源；**只记首次**，重复窃取不改时间 |
| `stolenCounts` | `Map<String, Integer>`（可选） | 重复窃取次数，仅用于 tooltip 附加行；不做排序依据 |
| `favoritesEntity` | `Set<String>`（entityId） | 照片页收藏 |
| `favoritesSet` | `Set<String>`（setId） | 套装页收藏（待确认 ⑧，默认保留） |
| `clickRule` | 枚举 `GRANT` / `EQUIP` | 点击网格规则（默认 `GRANT`） |
| `revision` | `int` | 每次变更 +1，客户端用于判断镜像是否过期 |

`copyOnDeath` 是硬要求（同羽毛槽）：NeoForge 复活只重建玩家实体，不 copy 就会「死一次图鉴全灰」。

### 4.2 写入点（唯一入口）

`ability/PhotoInjector.inject` 的 `ABILITY_STEAL` 成功分支（`player != null`，紧邻已有的
`TimecoreCurse.onStolenPhoto(player, entityId)`）：

```java
PhotoGalleryRecorder.onStolen(player, entityId);   // 里面：首次 → put(gameTime)；计数 +1；revision++；发增量同步
```

**旧存档迁移（必须有）**：`PlayerEvent.PlayerLoggedInEvent`（服务端）扫一次玩家物品栏 41 格 + 副手 +
Curios 全部槽位 + 相册内容物，凡带 `lensouls:stolen_entity` 的照片 id 且 `stolen` 里没有 → 记为
**时间 0**（最旧）。这样老玩家既有照片立刻解锁图鉴，且不会把它们的条目凭空顶到最前。

### 4.3 套装解锁口径

- 成员表：`PhotoSetLoader.getSets(entityId)`；套装成员：`PhotoSetRegistry.getMembers(setId)`。
- **套装已解锁** = 该 setId 的**全部登记成员**都在 `stolen` 里。
  （「已窃取」= 拍过，不要求照片还在身上 —— 与「已装备」`collectInstalledEntities` 是两套口径，别混用。）
- 进度 = 已窃取成员数 / 成员数（`PhotoSetDefs.effectiveCount(setId, tier)` 的成员数口径）。
- 特例 `boss_barrage`：成员表为空，进度 = 已窃取的首领照片**种类数**（`BossEntityLoader.isBoss`），阈值取该套装 tiers 的最大 count。

### 4.4 存档隔离（「不同存档不污染」）

| 层 | 做法 | 反例（禁止） |
|---|---|---|
| 服务端 | 数据只存在玩家附件里（保存进 `playerdata`，天然按存档隔离） | 用静态 `Map<UUID, …>` 存活数据 |
| 服务端静态缓存 | 只在单个 tick/单次调用内使用；如确需缓存，须在 `ServerStoppedEvent` / `PlayerLoggedOutEvent` 清空（参考 `FeatherAbyssHandler` 的「防跨存档污染」注释口径） | 按 UUID 常驻的全局表 |
| 客户端 | `PhotoGalleryClientCache` 是**镜像**，登录/切世界/断线（`ClientPlayerNetworkEvent.LoggingIn/LoggingOut`）时整体清空重建 | 客户端落盘一份图鉴数据 |
| 界面瞬时状态（当前页 / 滚动位置 / 搜索文本 / 开关） | 内存静态字段即可，**跟随世界重登重置**（写盘会跨存档串味） | 存进 `.dat` |

## 5. 网络层

| 方向 | 包 | 载荷 | 时机 |
|---|---|---|---|
| S2C | `PhotoGallerySyncPacket` | `stolen` 全量（id→time）、收藏全量、`clickRule`、`revision`（`FULL`）；或仅 `revision`（`PING`） | 登录、每次变更后、界面打开时 |
| C2S | `PhotoGalleryActionPacket` | `action` + `key`：`TOGGLE_FAVORITE`（`entity:<id>` / `set:<setId>`）、`SET_RULE`、`CLICK_CELL(entityId)` | 玩家操作 |
| C2S | `PhotoGalleryShortcutPacket` | `CLEAR_EQUIPPED` / `DEDUPE` | 快捷功能 |

- 全部 `registrar.playToServer/playToClient` 在 `PacketHandler` 双端注册（否则专用服务端缺通道）。
- 处理器一律 `try/catch` 兜底 + `context.enqueueWork`（项目惯例）。
- 客户端先乐观更新 UI，服务端同步包回来纠正显示（参考 `SummonerUiPrefs.applySummonLimitSync` 的写法）。
- `CLICK_CELL` 的结算结果（发放/装备/失败原因）通过 `FeatherToast` 本地提示；**不要**用动作栏消息（会被界面盖住，羽毛页已证）。

#### 6.1.2 三轮修订（1.6.50）：**面板区域回归参考图比例**（这条是硬约束）

二轮为了「把格子放大」去抬 k 上限，结果把面板撑到接近满屏 —— 实机反馈：
「**面板较大了、完全脱离一开始的区域设定，背景几乎全被模糊**」。

根因是**把面板尺寸当成了自由变量**。正确关系是：

```
① 面板区域 = 参考图比例 × 窗口   （0.614 × 0.796，直接来自参考图 1179×860 / 1920×1080）
② k = clamp(floor(min(面板区域宽 / K_W, 面板区域高 / K_H)), 20, 96)
③ 面板实际尺寸 = K_W·k × K_H·k   （必然 ≤ ① 的区域）
```

⇒ **想放大格子只能压非网格区（按钮/搜索条/行距），绝不能撑面板**。三轮把所有「按钮类」模块统一到同高：

| 项 | 二轮（1.6.49） | **三轮（1.6.50）** | 说明 |
|---|---|---|---|
| 面板区域 | 由 k 推导（≈满屏） | **窗口的 0.614 × 0.796** | 背景必须留得出来 |
| 开关行 / 快捷按钮 / 搜索条 / 页滑钮 | 0.34k / 0.34k / 0.50k / 0.50k | **统一 0.40k** | 二轮里滑钮比快捷按钮高 47%，看着「大一圈」 |

### 6.9 点击与悬停

**点击格子**

| 情形 | 行为 |
|---|---|
| 未解锁条目 | 只提示 `尚未窃取该生物的能力`（不发包、不发放） |
| 已解锁 + `GRANT` | 服务端 `EntityPhotographItem.create(id)` → `player.getInventory().add()`；返回 false → `player.drop(stack, false)` + 提示 `物品栏已满，照片已丢在脚下` |
| 已解锁 + `EQUIP` | 现查 `photograph` 槽数量（动态：`PhotoSpecialEffects.updatePhotoSlots` 与诅咒 e14 会 ±槽位）：① 已装备同 id → 提示 `该照片已装备`，**不重复装备、不覆盖已有槽位内容**；② 有空槽 → `stacks.setStackInSlot(i, stack)`；③ 无空槽 → 提示 `照片栏位已满` 并退化为发放到物品栏（待确认 ⑨） |
| 套装页格子 | 不做发放、不发物品；点击仅切换该格的选中/详情展开态（详情内容与悬停 tooltip 相同） |

**套装页格子与悬停（已确认口径：不渲染生物模型）**

- **格子内容**（三件，无模型）：套装名 + 进度行 + 完成标记。
  - 完成标记 = 进度满时加勾选色角标 + 高亮描边；未解锁时整体压暗（与照片页未解锁格子同款）。
  - 因为不渲染模型，套装页**不需要** §6.3 的模型缓存/scissor/深度清理（那套只在照片页生效），
    这也顺带消掉了套装页的崩溃面。
- **悬停 tooltip**（顺序固定）：
  1. 套装名；
  2. **套装效果**逐行（`PhotoSetRegistry.formatTier`，配色与照片 tooltip 一致）；
  3. `集齐 x/x/x 照片` —— 口径 = 该套装**登记的具体所需照片条目**（成员表动态读取）；
  4. `已收集 x/x`。
- 取值全部**现算**，不缓存快照：成员 = `PhotoSetRegistry.getMembers(setId)`；需求张数 =
  `PhotoSetDefs.effectiveCount(setId, tier)`；「已装」= `PhotoSetRegistry.collectInstalledEntities(player)`
  （Curios 照片槽 + 相册内容物，按实体去重）——**与照片 tooltip 的套装块用的是同一个方法**，别写第二份。
- 两条进度行 = **走语言键**（不硬编码中文与斜杠），格子与 tooltip 共用同一对键：

| 行 | 数字 | 含义 | lang 键（新增） |
|---|---|---|---|
| 集齐…照片 | `x/x/x` | **已装备张数 / 需求张数 / 该套装成员总数** | `gui.lensouls.photos.set.prog.need = 集齐 %s/%s/%s 照片` |
| 已收集 | `x/x` | **已窃取（= 图鉴已解锁）成员数 / 成员总数** | `gui.lensouls.photos.set.prog.collected = 已收集 %s/%s` |

- 现状（已查证）：`zh_cn.json` 里**目前没有**照片套装进度格式键；最接近的两处是
  ① 照片 tooltip 里那句 `已装 X/N`（在 `PhotoSetRegistry.appendTooltip` 里**硬编码中文**，不在 lang 文件）；
  ② `gui.lensouls.curse.prog.*` 家族（`%s / %s`、`%s 种 / %s 种`…，是 lang 键范式）。
  ⇒ 本功能新增上述 2 个键；**照片物品 tooltip 的套装块维持现有口径不变**（成员名着绿/灰 + `已装 X/N`），
  但顺手把那句硬编码迁到 lang 键（建议 `gui.lensouls.photos.prog.equipped = 已装 %s/%s`），避免以后两处文案不一致。

**悬停 tooltip（照片页）**

- 已解锁：`ItemStack hover = EntityPhotographItem.create(entityId);`
  `graphics.renderTooltip(font, getTooltipFromItem(minecraft, hover), hover.getTooltipImage(), mouseX, mouseY);`
  → 自动带上套装块 / 效果描述 / 属性 / 元素活性（与实物逐字一致，**不要**手工拼 tooltip 行）。
- 未解锁：名称 + `尚未窃取该生物的能力` + 一行指引（用能力窃取拍照即可解锁）。
- 滑钮：当前页名（§6.5）。

### 6.10 排序

**照片页**（参考 Remorphed 的 tier 思路；口径已确认：收藏 → 最新首拍 → 未窃取）

```
tier 0  收藏（favoritesEntity 命中）
tier 1  已窃取：按「首次窃取 gameTime」倒序（最新首拍在最上；迁移补记的 time=0 自然排最后）
tier 2  未窃取：minecraft 优先 → 其余按模组显示名（ModList displayName）→ 组内按当前语言显示名
        翻译键缺失（Language.getInstance().has(id) 为 false）者垫底
tier 内同值时按实体 id 字典序收口（保证顺序稳定、不随 JVM/Map 迭代顺序抖动）
```

**套装页**：tier 0 收藏 → tier 1 进度降序（同进度按 setId 字典序）→ 全部按此序（未解锁套装只在开关打开时出现）。


## 11. 必须知道的坑（汇总，全部有来源）

1. **模型写完深度缓冲会遮住后续 GUI 文字** → 模型全部画完后 `clear(DEPTH)` + `disableDepthTest`，画完 overlay 再 `enableDepthTest`。（Remorphed `SummonMenuScreen:221-248`）
2. **异常路径必须 `finally disableScissor()`**，否则整屏后续渲染被裁掉。（Remorphed `SummonEntityWidget:161-173`）
3. **部分实体在 GUI 渲染会抛异常** → 每格 try/catch + `crashed` 标记，不重试。
4. **巨型生物靠 scissor 约束**，不要试图按 `bbWidth/bbHeight` 分别缩放去「塞进」格子（会变形）。
5. **`type.create(level)` 可能抛异常/返回 null/返回非 Mob** → 缓存构建期 try/catch 跳过（Remorphed `SummonEntitiesData.loadAll`）。
6. **`GlassPanel` 前必须 `graphics.flush()`**（GUI `fill/blit` 是延迟批处理，否则玻璃糊成上一帧内容）。
7. **没有隐藏的 41 个背包槽 → 服务端改背包客户端看不见**（`FeatherSlotMenu` / `ReinforceMenu` 已证）。
8. **`Screen` 必须实现 `MenuAccess<M>`** 才能注册进 `RegisterMenuScreensEvent`；`render` 不调 `super.render`。
9. **`ContainerData` 才是小状态同步的正路**（`addDataSlots` + `SimpleContainerData`），不要为它写自定义包。
10. **命令根 `requires` 会连带子命令** → 权限必须下移（§8）。
11. **附件必须 `serializable + copyOnDeath`**，否则死亡/重进丢解锁数据（`FeatherAttachments` javadoc）。
12. **静态客户端缓存切世界必须清**（`ClientPlayerNetworkEvent.LoggingIn/LoggingOut`），否则上一个存档的图鉴留到下一个存档（跨存档污染）。
13. **拼音字典构建数百毫秒** → 后台线程 + 主线程子串兜底；**PinIn 拉丁大小写敏感** → 查询前 `toLowerCase`。（`ReinforceSearchContext` 已证）
14. **热路径判存在性用 `CustomData.contains`，不要 `copyTag()`**（每个格子/每次伤害都会调 → 整份 NBT 复制）。（`CuriosIntegration` javadoc）
15. **相机照片界面会抢右键/左键**：本界面若涉及照片物品的左右键，注意 `PhotographItem.use` 在客户端会打开照片查看界面（装机路径踩过，见 AGENTS.md 1.4.99 节）。本界面不发物品右键行为，保持只读。
16. **贴图必须是真 PNG**：给定 `button.png` 实为 WebP，直接塞进资源包不会被加载（转换命令见 §9；两张图已转换入库）。
17. **换 cover 背景素材必须同步改 `Background` record 里的 texW/texH**：羽毛页曾用 1620×1080 素材而常量仍是 1920×1080，实机症状是「y 方向被拉长」。尺寸与路径写在同一处就是为了不再漏改。
18. **磨砂玻璃不要自调参数**：`GlassPanel`（模糊半径、σ = radius/3）与羽毛页共用同一份实现，只要对齐 `PANEL_RADIUS = 10.0F` 与 `GLASS_TINT = 0x8C121A24` 两个值，观感即一致。
19. **展开的列表（补全弹窗 / 快捷功能面板）必须先 `graphics.flush()` 再画底板**：底板走立即模式的 `RoundedRect`，
   而格子名称/开关文字等都是**延迟批处理** —— 不先落盘，那些旧文字会在之后才画，**直接盖在弹窗底板上**（实测症状：文字重叠、像没遮住）。
20. **弹窗/列表覆盖的屏幕区域要屏蔽下方网格的悬停与 tooltip**：`indexAt` 只按网格矩形判定，弹窗恰好压在网格上（补全弹窗高 6×14px ≈ 1.5 行），
   不屏蔽就会出现「鼠标在列表上、下方格子却弹 tooltip」。实现：`mouseOverPopup()`（补全弹窗 + 快捷功能面板）统一在
   `updateHover` 与 `renderTooltips` 里短路，并**每帧重算悬停**（弹窗可能在鼠标不动时展开）。
21. **语言文件只追加键**，改完必须 `python -c "import json,io;json.load(io.open(path,encoding='utf-8'))"` 校验。
22. **`stack.get(DataComponents.CUSTOM_DATA)` 为空**是常态（新照片、JEI 展示），所有读取都要判空。

### 15.2 本轮新增的两条硬坑

1. **`PoseStack.clear()` 在 1.21.1 只是「栈深是否为 1」的查询，并不清栈**（`javap -c` 核实：只做 `size()==1` 判断后 `ireturn`）。
   所以模型渲染异常时**不能**靠它恢复姿态栈 —— 正确做法是「自己 `pushPose` 一对 + catch 里把矩阵还原成进入前的快照 + `finally popPose`」，
   这样即使 Vanilla 在 pop 之前抛异常，多留的那一层也会被我们这次 pop 收掉（留下的是恒等矩阵，对后续绘制无影响）。
2. **PowerShell 的 `Set-Content -Encoding UTF8` 会写 BOM**（PS 5.1），Java 编译器直接报
   `非法字符: '\ufeff'`。用 pwsh 批量改 `.java` / `.gradle.properties` 后必须剥 BOM（本项目已在构建前检查过一次：
   `PhotoGalleryScreen.java` 与 `gradle.properties` 都被写过 BOM）。

### 15.12 十轮反馈（1.6.57）

| 反馈 | 落点 |
|---|---|
| **快捷功能面板仍被搜索框文字挡着** | 前几轮分别在浮层**前面**加 flush，但浮层之后仍有延迟提交（页滑钮 / tooltip / 浮动提示），顺序始终留有被反超的余地。现在把**两个浮层改到整帧最后绘制**：<br>`… 搜索框文字 → 页滑钮 → tooltip → 浮动提示 → ★ graphics.flush() → 补全弹窗 → flush() → 快捷功能面板 → 关闭按钮`<br>flush 落盘一切延迟文字之后，浮层用立即模式底板盖上去 ⇒ **不论此前谁提交了什么，浮层都在最上层**，顺序问题从根上消失。这条顺序是硬约束，写进 §6.8。 |
| **未解锁时的灰框覆盖没带圆角** | 暗罩原来用 `graphics.fill(...)` 直角矩形，会在圆角格子的四个角上多盖出一块方形黑角。现在照片格与套装格都改用 `RoundedRect.roundedRect(..., radiusCell(), 0x88000000, 0x88000000, 0x33FFFFFF, 1.0F)` —— **与格子同半径**，并保留 1px 描边（否则未解锁格看着"没边"）。 |

> **浮层绘制顺序（硬约束）**：本界面只有两个浮层 —— **补全弹窗**与**快捷功能面板**。
> 两者底板都是**立即模式**（`RoundedRect` → `Tesselator` + `BufferUploader.drawWithShader`），
> 而搜索框文字 / 格子名称 / 开关文字 / tooltip / 浮动提示全是**延迟批处理**（`GuiGraphics.bufferSource`）。
> **凡是要盖住文字、图标、模型的浮层，必须排在整帧最后、且前面显式 `graphics.flush()`。**
> 只"在浮层前 flush"是不够的：只要浮层之后还有延迟提交，落盘顺序就还有被反超的可能（本项目连踩三次）。

### 15.20 十七轮反馈（1.6.65）：一键清空恒提示「卸下 0 个」

**现象**：点「清空当前装备的全部照片饰品」，不论实际卸下几件，提示永远是 `清空 0 个照片饰品`（但确实卸下来了、也确实退回了物品栏）。

**根因（经典陷阱）**：`Inventory.add(ItemStack)` 是把数量搬进背包后**原地把该 stack 清成 0**（原版语义）。
原代码是「先 `give(player, taken)`、再 `taken.getCount()`」⇒ 读到的是**已被清空的 0**：

```java
ItemStack taken = extract(...);
if (taken.isEmpty()) continue;
give(player, taken);              // ← 这一步把 taken 消耗掉了
moved += taken.getCount();        // ← 恒为 0
```

**修法**：**先读数量再搬运**（`clearEquipped` 与 `dedupe` 两处同病同修），并把这条写进 `give()` 的 javadoc：

```java
int count = taken.getCount();     // ★ 必须先读
give(player, taken);
moved += count;
```

> **通则**：任何「先 `Inventory.add` / `ItemHandler.insertItem` 再统计」的代码都会读到 0 ——
> 这类 API 的契约就是「消耗入参 stack」。要计数一律**在搬运之前**取 `getCount()`（或传 `stack.copy()`）。

### 15.21 十八轮反馈（1.6.66）：照片栏满 / 未落槽时如实回退为「发放到物品栏」

**反馈**：照片槽位满时，提示不该固定写「已装备照片」，要如实交代「照片栏已满，发放到物品栏」。

**根因**：`setEquippedCurio(identifier, index, stack)` **不抛异常也不保证落槽** —— 当该槽此刻
不可用（被槽位修饰符裁掉 / 饰品与槽不匹配等）时，Curios 会把那件饰品**直接退回玩家背包**
（同一个 `ItemStack` 实例被消耗）。原实现写入后立即 `return EQUIPPED`，于是出现
「实物进了物品栏、提示却写『已装备照片』」。

**修法**（`PhotoGallerySettlement.equip`）：

```java
opt.get().setEquippedCurio(PHOTO_SLOT, i, photo);
ItemStack landed = stacks.getStackInSlot(i);                       // ★ 回读校验
if (!landed.isEmpty() && entityId.equals(photoEntityId(landed))) return EQUIPPED;
if (photo.isEmpty()) return NO_SLOT;   // 已被 Curios 退回背包 ⇒ 别再试、也别补发（否则两份）
```

- 校验不过 → 继续找下一个空槽；全部不行 → `NO_SLOT` → 调用方**如实**走发放回退
  （`give()` 收到空堆会安全跳过，不会重复发放）。
- 文案按要求改：`gui.lensouls.photos.toast.no_slot`
  zh `照片栏已满，发放到物品栏` / en `Photo slots full - given to your inventory`。

| 情况 | 提示 |
|---|---|
| 有空槽且真的落槽 | 已装备照片 |
| 该生物照片已在（照片槽或相册里） | 该照片已装备 |
| **没有可用空槽 / 写入未落槽（被 Curios 退回）** | **照片栏已满，发放到物品栏** |
| 物品栏也满 | 物品栏已满，照片已丢在脚下 |
