## 0. 三条硬规则

1. **玩家没有韧性/破定。** 那套全部打在 BOSS 身上。任何"破定/韧性失效"的表述，都要改写成玩家侧
   （受伤倍率 / 真伤化 / 治疗倍率 / 原版属性 / 资源）。
2. **不许和已有诅咒抢同一根轴。** 已占用：
   荒厄遗咒（相机能力、元素亲和、药水活性、附加伤害、空余照片饰品栏位）、元素觉醒者（活性等级成长、元素 DoT）、
   折翼沉渊（经验、生命上限、挖方块生怪、食物回血、扭曲值）。
3. **惩罚要有力度。** 条件必须高频或无条件；被剥夺的必须是核心玩法
   （拍照削韧 → 照片套装 → 元素活性与 DoT → 复制之魂 → 照片弹幕 → 次元枪/引力枪）。
   ⚠ **「镜魂」「指南针」这类边缘系统不算惩罚**；⚠ **「Y≥320」这类几乎不触发的条件等于没有惩罚**。

## 1. 七个诅咒（唯一对照表）

> 表格列序统一为 `诅咒效果 → 反转条件 → 反转后`。
> ①②③ 的**反转条件是整款共用**，写在表格下方；**④⑤⑥⑦ 全部逐条反转**，条件写在表内。
> 标记：`▲` = 增益（反转后加强）；`▼` = 减益；无标记 = 该条不参与取反。
> **⑤⑥⑦ 的条目名走「文雅主名」**（铁序 / 秘仪 / 誓约 三系），**机制一律看该条的「诅咒效果」列**，界面 tooltip 同口径。
> ⚠ 全文的「**无法发动相机能力**」一律指 **只禁能力照片**（摄魂术能力的产出），**普通拍照不受影响**。
> ⚠ **反转达成即即时生效，且一次达成永久保留**（不需要在界面点确认，也不因死亡 / 摘除 / 掉线回退）。
> ⚠ **反转默认移除该条的诅咒效果**（由反转后效果取代）；**仅当条目标注〔保留〕时**，原诅咒与反转后效果共存（当前有两条：① 荒厄·蚀峰、② 扭曲·狂喜）。
> ⚠ **叠加口径（仅垂翅已定）**：铁序·垂翅 与照片「创造飞行」的飞行惩罚——**诅咒态乘算**（×0.5 × 0.1 = ×0.05 = −95%）、**反转后加算**（+25% − 90% = 净 −65%）。**这不是通用规则**，其余条目的叠加口径见 §2「叠加口径（定稿）」。
> ⚠ **用词口径**：**系统 / UI 措辞用「羽毛」**（羽毛栏、点击其他已装备的羽毛…）；**机制文本仍用「诅咒」**（在该诅咒下、解除诅咒、被本条诅咒折损）。
> ⚠ **反转文案口径**：只有「**整层失效**」的条目才写「解除诅咒 / 不再有诅咒」（当前 3 条：`秘仪·篡命`、`誓约·断供`、`誓约·易手`）；**「数值取反」与「追加新机制」类一律不写**，避免 57 条文案啰嗦。

## 2. 受难条件规范

**能用的条件类型**（都可测量、我们环境都支持）：

| 类型          | 例子                                          |
| ----------- | ------------------------------------------- |
| 累计承受某类伤害并存活 | 累计承受 5000 点伤害 / 3000 点物理伤害                  |
| 单次受击阈值      | 单次受到 ≥15 点摔落伤害并存活                           |
| 击杀指定 BOSS   | 击杀暮色巫妖 / 远古遗魂 / 蔓生巨像 / 斯库拉 / 末影守卫 / 炼狱飞龙 / 堕落圣骑 / 监守者 |
| 击杀数量        | 击杀 3 只 BOSS / 500 只生物                       |
| 资源累积        | 累计造成 5000 点元素伤害 / 累计治疗 2000 点               |
| 行为累积        | 累计挖掘 1000 个方块 / 累计 500 次攻击丢失                |
| 状态维持        | 在饥饿 V 状态下击杀 200 只 / 在缓慢状态下累计走地 10000 格              |

**「并存活」判定规则**：条件里写了「并存活」的 → **死亡即重置该计数**（如 `铁序·余悸`）；
**没写「并存活」的 → 跨死亡/掉线持久化，不清零**（如 `铁序·夺佑` 的 5000 点、`誓约·叛主` 的雪球次数）。

**叠加口径（定稿）**

**① 不同乘区之间一律乘算**（造成伤害 × 受伤 × 护甲 × 元素活性 × 韧性减伤）—— 原版/NeoForge 既定行为，不由本系统决定。

**② 同一乘区内，按轴分三类**：

| 轴 | 诅咒态 | 反转 / 祝福态 | 理由 |
|---|---|---|---|
| **受伤侧** | 乘算 | 乘算 | 加算会累到 ≤ −100% 变免疫；加伤侧加算会让多个诅咒同戴瞬间秒杀玩家 |
| **输出侧** | 乘算 | **加算** | 惩罚乘算不会叠成"禁武"；补偿加算才抵消得动巨额惩罚（如照片飞行 −90%） |
| **治疗侧** | 乘算 | 乘算 | 加算会到负值 = 完全禁疗；且 LivingHealEvent 本就是乘算链 |

**③ 点数与资源类直接加算**：护甲 ±N、韧性伤害 ±N、反弹 %、栏位 ±N、冷却 ±N%、时运/抢夺 ±N、掉落 ±N、上限 ±N、每 1% 减速 +N 点伤害、每级正数活性 +N 点附加伤害。

**④ 逐条归属**（25 条百分比修正）：

| 轴 | 条目 |
|---|---|
| 输出侧 | ①蚀峰、②苦楚、④挫败、④疯狂、⑤钝锋、**⑤垂翅**、⑥蚀力、⑦断供、⑦叛主、⑦神愤、⑦博识、⑦灵通 |
| 受伤侧 | ①蚀峰、②外伤、②苦楚、③躁动、④安魂曲、④疯狂、④恶意、⑤盈伤、⑤余悸、⑥献祭、⑥穿甲 |
| 治疗侧 | ⑤绝疗、⑤饥禁、⑤止息、⑥竭泉、⑥血偿 |

**⑤ 已定实例**：铁序·垂翅 与照片「创造飞行」—— 诅咒态**乘算**（×0.05 = −95%）、反转后**加算**（净 −65%）。

**⑥ 实现**：现有 DamageHandler / PhotoDamageHandler / ToughnessDamageHandler 都是乘算链；"反转后加算"需改为 d × (1 + Σ 反转修正) 形式，并在所有乘算之后统一收口一次。

**禁止的条件**：依赖我们没装的模组（灵魂能量、寒流伤害、寒流/穿孔/灵魂破裂/永恒/失重）、
不可测量的数值（瞬时速度 200、速度 100）、几乎不触发的位置条件（Y≥320）、模糊描述（"死亡边缘触发不死图腾"）。

**关于原稿的"死亡回退"（残晶：死亡随机重置一条已修正的诅咒）**：**不采用**。
理由：我们的反转条件本身就是"受难成就"（累计承受 5000 伤害、累计治疗 2000 点、低血量击杀 200 只等），再叠加死亡回退等于
**双重惩罚**，会逼玩家为了保进度不敢打 BOSS，与我们的 BOSS 玩法直接冲突。

- 入口：FeatherScreen 里**点击任意方框** → 弹出**列表弹窗**（标题显示"第 N 槽"）。

- **悬停某行 → 显示该款道具的完整 tooltip**（常显 + Shift 两段，见 §4.2）。

  纯二字名玩家联想不到效果，短标直述机制；tooltip 里再展开完整数值。

- ⚠ 弹窗内**必须显示提示行**：「生存模式不可撤下，只能左键更换；创造模式可右键撤下」。

## 5. 数据结构与同步

```java
CurseStateData implements INBTSerializable<CompoundTag>   // 玩家附件，copyOnDeath
├── ItemStack[7] slots      // FeatherSlotData 的 SLOTS 由 5 改为 **7**；旧存档后 2 槽按空补齐
├── int reversedMask        // 位掩码：①3 + ②3 + ③2 + ④12 + ⑤23 + ⑥7 + ⑦7 = 57 位
├── long[] progress         // 逐条受难进度（与掩码同序）
└── boolean[] locked        // 沿用现有锁定语义
```

- 反转与进度 **服务端权威**，S2C 同步（客户端只用于列表与 tooltip 显示）。
- **反转一次达成即永久解锁**：`reversedMask` 置位后**永不复位**（不因死亡 / 摘除 / 掉线回退）。
- 进度**只在该款被选进槽位期间**累计；未选中不累计。
- 旧存档缺字段按 0 补齐。

## 7. 实现落点（② 的满值死亡三件套）

| 机制                       | 现状落点                                                                                                                                                                                                             | 要动的地方                                                                                                                                                                                                                                                       |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 强制掉落（无视 `keepInventory`） | `mixin/PlayerDropEquipmentMixin` 已实现：`@Redirect dropEquipment` 里读 `GameRules.RULE_KEEPINVENTORY`，条件 = `hasTwitcher(sp) && persistentData.getBoolean(KEY_FORCE_DROP)` ⇒ 返回 false（不豁免），消费后清除 `lensouls:force_drop` | 现成，只需保证 `KEY_FORCE_DROP` 在「满扭曲值死亡」时被写入                                                                                                                                                                                                                      |
| 虚影核心托管                   | `handler/PhantomRemnantHandler` 的死亡结算**在 `keepInventory=true` 时完全不生效**（源码注释已明说） ⇒ 玩家开着死亡不掉落时，本应托管的物品**反而会原地落到地上**                                                                                                | **必须改掉这条守卫**：托管改由「满值死亡」这一事件驱动（与游戏规则解耦），`keepInventory` 不再作为前置                                                                                                                                                                                               |
| 扭曲值满值判定与写标记              | `handler/FeatherTwitcherHandler.onDeath`：扭曲值**达到 100**（本版改为受击驱动，不再"死亡 +10"）时 `getTwist() >= MAX_TWIST(100)` → 尝试生成扭曲者 + 写根键 `lensouls:force_drop`                                                                                  | 两个 handler 都是 `LivingDeathEvent`，**必须显式定序**（托管要读到尚未被清空的背包）⇒ 用共享静态标记：`FeatherTwitcherHandler.onDeath` 判定满值后先置标记，`PhantomRemnantHandler` 再据标记执行托管，最后才让 mixin 消费 `FORCE_DROP`。扭曲值等跨死亡数据一律走 `persisted`（`Player.PERSISTED_NBT_TAG`）子键——直接放根上复活后会丢（实测 twist 变 0） |

> ② 的扭曲值来源已改为**受击驱动**（狂喜）；但「扭曲值涨到 100 → 死亡时判定满值 → 写标记」这条链路**不变**。

> 口径统一：**「爆物品」不是没收，而是「必须付出一次回收成本」**——有虚影核心就只是跑一趟取回，
> 没虚影核心才真的散落（可能丢失）。这符合 §0 第 3 条「惩罚要有力度」，但不至于一死清零。

**⑦ 誓约·易手（强制换手）实现守卫**——不做这几条会出物品复制/丢失事故：

| 守卫                                                                  | 原因                                     |
| ------------------------------------------------------------------- | -------------------------------------- |
| 只在「没开别的容器」且「光标为空」时交换                                                | 否则物品停在 `containerMenu` 光标或容器槽里会被吞 / 复制 |
| 旁观者、创造模式、死亡瞬间、切维度时不触发                                               | 这几种状态下切换手持会丢物品                         |
| 丢出用 `player.drop(stack, false)` **丢在脚下**，不往外抛                       | 3% 丢出若抛远，在岩浆/虚空边就是直接销毁，玩家会当成恶性 bug     |
| 交换后 `broadcastChanges()` + 播一个音效 + 动作栏提示                            | 不给反馈会被当成客户端显示错乱上报（弹幕/虚影都踩过这个坑）         |
| 与 BetterCombat / 双持相关模组交互时只换 `Inventory` 槽位，不碰 `ItemInHandRenderer` | 直接改渲染层会与对方模组打架                         |

**⑦ 誓约·易手 的两条定案**：

- **力量 X 时长 10 秒；触发后冷却 7 秒** —— 5% 掷骰只在冷却结束后生效，防狂按切换键刷满。
- **3% 丢物品不排除任何物品**（含弱点透镜照片 / 已强化武器）—— 即**可能永久丢失不可恢复物**，这是刻意的惩罚力度。
