# 机制速查与坑位

> 从旧 AGENTS.md 顶部章节原样抽出（2026-08/09 编写）。**以 src/main 代码为准**，本文只是地图与提醒。
> 某个系统怎么运转、为什么这么改，在这个文件里；历史上谁改了什么，看 `docs/档案/` 里的批次记录。
## 照片注入管线（拍照能力系统）

```
FrameAddedEvent → PhotoInjectionHandler.onFrameAdded
  → pendingAbilities.put(exposureId, ability)   ← 按帧 ID 存能力，与玩家当前能力解耦

出片时：
  PolaroidPrintMixin（拍立得）/ LightroomInjectMixin（Exposure 暗房）
  → pollAbility(exposureId) → 注入照片 CustomData
```

- 能力按 **exposureId**（Frame identifier 字符串）索引，不用玩家 UUID 队列——之前用队列导致切能力后出片错乱
- `PolaroidPrintMixin` 用 `@ModifyArg` 拦截 `photograph` 传参路径（`Inventory.setItem` / `StackedPhotographsItem.addPhotographOnTop` / `Player.drop`），**不要用 `LocalCapture`**（ExposurePolaroid JAR 缺调试信息会静默失败）
- 能力窃取/弱点透镜：实体为空或无注册效果 → 不出能力照片（普通照片）
- 自定义调试日志前缀：`[PhotoInject]`、`[Polaroid]`

## 渲染系统（易踩坑）

- **描边是两条独立 FBO 管线 + 一个「谁描」开关**：
  ① **实体描边**（BOSS 四色流动 / 定身冰蓝）= `ability/client/MaskRenderTypes` 把实体写进 `FrozenOutlineManager` 的 mask FBO，
  帧末由 `goldOutlineShader`（BOSS 四色流动）/ `maskShader`（冰蓝定身）合成；「谁描、什么颜色」由
  `mixin/client/EntityBossOutlineMixin`（改 `isCurrentlyGlowing`、跑 `PartEntity` 父体解析）+ `client/outline/BossOutlineColors` 决定。
  ② **第一人称手持物** = `client/itemoutline/*`：自建 `TextureTarget`、在 `RenderGuiEvent.Pre` 跑 `item_outline_composite`，
  与 ① 完全独立；必须走 `MultiBufferSource` / RenderType，裸 GL 会破坏 Iris。
  旧方案（`BossOutlineManager` / `BossMaskRenderTypes` / `SoulOutlineCompat` / `ItemInHandRendererMixin`）已移出 `src/main`，
  备份在 `outline-system/`，说明见 `docs/档案/描边系统-旧方案/`——**别把旧类名当现行事实**（`MaskRenderTypes` 还在用，`BossMaskRenderTypes` 已删）。
- 多子部件 BOSS（暮色 `TFPart extends PartEntity`、末影龙）是独立渲染的实体，状态要沿 `getParent()` 取父体，
  否则出现「头白、身子红」这类半色描边。
- 韧性条位置平滑参数与 `GravityTetherRenderer.POS_DELAY`（0.06）对齐，受伤时减半。

## 伤害限制绕过（灾变/传奇怪物）

- **NeoForge 1.21.1 坑：`LivingDamageEvent.Pre` 的护甲在事件前已结算**（反编译 `actuallyHurt`：先 `setReduction(ARMOR)` 再抛 Pre）。事件里加伤/减伤的基数**必须用 `event.getNewDamage()`**（护甲后），用 `getOriginalDamage()` 做基数会撤销护甲（骷髅箭射玩家从 1 血变 4 血事故）。已修：`DamageHandler` 元素弱点、`PhotoDamageHandler` 摄魂增伤、`PhotoSpecialEffects` 飞行惩罚
- 灾变桶机制（反编译确认）：`damageBucket += amount`，桶超 `DamageCap()` 后伤害变 0.1——`CataclysmDamageBucketMixin` HEAD 无条件清桶
- 单次上限：`Math.min(DamageCap(), amount)`，`@ModifyArg` 在 `ElementBypassHelper.shouldBypassCap()` 时返回 `Float.MAX_VALUE`；破定期间 + 元素弱点武器 → 绕上限（不限活性等级）
- 幻灵（借真身实体，persistentData 标记 `lensouls:phantom`）攻击由 `entity/PhantomDamageHandler` 在 `LivingDamageEvent.Pre` 覆盖为固定穿透伤害（`PEN_DAMAGE = {20,36,42,70,74}`，按 `lensouls:phantom_level` 1–5 取值）

## 1.21.1 合成/容器机制（复制之魂实现验证，反编译确认）

- **`Recipe.getResultItem(CraftingInput)` 在 1.21.1 不存在**——覆写会编译报错"不会覆盖超类型方法"。动态输出只能覆写 `assemble(CraftingInput, HolderLookup)`（`CraftingMenu.slotChangedCraftingGrid` 每次格子变化都调它，工作台预览即动态）
- **"原物品不消耗"实现**：覆写 `Recipe.getRemainingItems(CraftingInput)`（NeoForge 补丁的泛型版，返回按槽 `NonNullList<ItemStack>`，可带 NBT）。`ResultSlot.onTake` 流程：每槽 `removeItem(1)` → `RecipeManager.getRemainingItemsFor` → 非空 remaining 放回原槽（同组件 grow 合并）。这就是"消耗水保留桶"的服务端版本，`CopySoulRecipe` 即范例
- 工作台硬限制：结果槽仅 1 堆、输入全消耗（无 NeoForge hook 可改）——"输出 2 个"或"保留原物"在纯配方层不可能
- **铁砧两个坑**（AnvilMenu 反编译）：`mayPickup` 要求 **cost > 0 且玩家等级 ≥ cost** 才可取出（cost=0 拿不出）；`onTake` 取出时左槽 `setItem(0, EMPTY)` 直接清空——铁砧无法实现"保留左槽物品"

## 新道具机制（次元瓶/复制之魂）

- **次元瓶**：使用次数 = 耐久条（总耐久 = 1 + 已到访维度数）。维度列表**存物品自身**（stack CUSTOM_DATA `lensouls:visited_list`，`recordVisited` 每 20 tick 由 `inventoryTick` 记录，背包任意槽位生效，死亡/换人后不丢失）；旧玩家 persistentData（`lensouls/visited_dimensions`）首次记录时迁移。30s 恢复 1 点：`inventoryTick` 每 20 tick + `lensouls:last_regen` 时间戳（使用/恢复时重置）
- **复制之魂**：BOSS（有 boss bar）死亡掉落 5-20 个；工作台复制配方（见上）
- **BOSS 判定（无注册表可查）**：1.21.1 `MinecraftServer` 无 `getBossOverlay`（仅 `getCustomBossEvents`，那是 /bossbar 命令用的），原版 EnderDragon/Wither 的 bossEvent 是私有字段不暴露。通用检测 = 反射沿类层次找 `BossEvent` 类型字段（`CopySoulDropHandler.hasBossBar`，ServerBossEvent 再查 `isVisible()`），覆盖原版+暮色 BossEventServer+各 mod BOSS

## 构建与环境（踩过的）

- 在**仓库根**跑（`lensouls-template-1.21.1/`），`./gradlew build` / `.\gradlew.bat build`（pwsh）；
  `compileJava` 只编 Java 最快，`runClient` / `runServer` / `runData` 都有（`build.gradle` 里四套 run 配置）。
- **构建前递增 `gradle.properties` 的 `mod_version`**，否则同名 jar 覆盖、分不清哪个版本。
- **客户端开着时 `createMinecraftArtifacts` 会因 merged jar 被锁失败**（`AccessDeniedException ... is locked by`）
  ——不是代码问题；dev 客户端本身编译源码，不需要先构建 jar。
- 改了 resources（着色器 json、纹理、`*.mixins.json`）要先 `clean` 再 build，否则可能用到缓存。
- `build/refmap` 下自动生成的文件会报重复 refmap 警告——**无视它**；手维护的是
  `src/main/resources/lensouls.mixins.refmap.json` 那个空占位。
- compileOnly 的灾变/传奇怪物 jar 在仓库 `libs/`（flatDir，`compileOnly "lensouls:..."`），不在 gradle 缓存里。
- 必须 **JDK 21**；`./gradlew` 报权限问题时用 `bash gradlew` 或 `cmd /c gradlew.bat`。
- 首次 `runClient` 会下载 MC assets（1–2 GB），之后走缓存；`run/config/`、`run/logs/` 是运行期目录。

## 幻灵（BossPhantom）借真身（1.8.98–1.8.101）

- **唯一路径**：`BossPhantomManager.startBorrowedEntity` 反射构造真身类实例 → `addFreshEntity` → `setInvulnerable(true)`
  （原版无敌标签：免索敌 + `hurt` 直接挡掉）→ 清 BOSS 血条 → `setTarget(主人最近攻击目标/最近敌对)`。
  **不 `setNoAi`：靠它自己的 AI 出招**（旧文档说的「幻灵只表演」早已过时）。
- **无模组降级路径已删除**：类型未登记 / 模组未加载 → 直接提示 `message.lensouls.phantom_unavailable` 不开幕，
  不再退 `BossPhantomEntity` 假表演（比不开更糟）。开不了要在切旁观/扣效果之前就拒绝。
- **时序**：`SPECTATOR_TICKS = 40`（只旁观 2 秒）后玩家恢复游戏模式，与幻灵**并肩作战**到
  `PHANTOM_TOTAL_TICKS = 200`（10 秒）结束。任何「玩家全程旁观」的推断都是错的。
- **编队型 BOSS（暮色幻影骑士）**：借真身时另补 4 名兄弟骑士（编号 1..4、同反射构造/幻灵标记/无敌/清血条、
  环 2.5 格、同目标），`KNIGHT_SQUAD` 登记，`endPhantom → discardKnightSquad` 一起清。
  TF 的 `getNearbyKnights()` **包含自己**（孤身一只是 size=1、不会崩），但它要 0..4 号配合才有正常编队表现。
- **友方判定一律走 `util/AllyFilter`**：`isFriendly(viewer, target)` = 玩家 ‖ 任意驯服宠物 ‖ 自家召唤物（幻灵/幻翼）
  ‖ 第三方辅助作战单位 ‖ 同乘。幻灵选敌、每 tick 重定向（本体 + 兄弟 + 召唤物）、主人「最近攻击目标」记录都走这一份；
  **不要再手写 `instanceof Player` + `isTamedPet` 之类的组合**。
- 幻灵→玩家的伤害由 `PhantomDamageHandler` 取消，但那只拦伤害、**不拦仇恨**：仇恨必须每 tick 重定向，
  否则玩家（2 秒后就恢复模式）会被自家兄弟追着砍（伤害 0 但带击退/受击动画）。

## 「写坏坐标」类崩服（NaN）

- 症状：服务端 `IllegalArgumentException: Bound must be positive`，栈顶是第三方 AI（如 TF
  `PhantomUpdateFormationAndMoveGoal:142` 的 `nextInt(nearbyKnights.size())`），崩溃报告里
  `Entity's Exact location / Momentum: NaN, NaN, NaN`。
- **真根因（1.8.105 定案，实机 jar 4.8.3345 `javap -c` 逐条核对）**：暮色
  `KnightPhantom.knockback(double strength, double x, double z)` **自己重写且不调 `super`**：
  `float f = Mth.sqrt((float)(x*x + z*z)); setDeltaMovement(delta.scale(0.5)); delta.x -= x / f * 0.2;`
  ——`x = z = 0` 时就是 `0.0 / 0.0 = NaN`，而原版 `LivingEntity.knockback` 里
  「`x²+z² < 1e-5` 就随机一个极小方向」的保护被绕开，`LivingKnockBackEvent` 也不派发。
- 什么时候 `x = z = 0`：**不带坐标的伤害源**。`new DamageSource(holder)`（fdbosses 的
  `GEBURAH_LASER_STRIKE_SOURCE` 正是裸构造）和 `minecraft:generic` 在 `LivingEntity.hurt` 里
  `getSourcePosition()` 返回 null ⇒ 跳过方向计算 ⇒ 直接 `knockback(0.4, 0, 0)`。
  其它生物没事（原版会把零方向随机化），只有这个骑士炸 ⇒ 速度 NaN ⇒ 下一 tick `move()` 写进坐标
  ⇒ 它自己的包围盒 NaN ⇒ `getEntitiesOfClass` 连自己都查不到 ⇒ `nextInt(0)`。
- 修法：`mixin/compat/TFKnightKnockbackNaNGuardMixin` 用 `@ModifyVariable` 兜住参数——
  `x` 为 0/NaN/Inf 时换成 `1.0E-4`（保证 `f ≥ |x| > 0`），`z` 只在非有限时归零。
  不动暮色的公式，方向正常时原样透传，代价是每次击退两次比较。
- **别再用「每 tick 扫玩家周围 N 格的实体」当通用保险**（1.8.104 那样做被否）：`inflate(96)` 等于
  12³=1728 次分区探测 + 盒内每个实体一次 UUID 哈希，实测 0.3~0.8 ms/tick/玩家（常驻 1~3% tick 预算，
  多人按人数翻倍），「救回原位」的 UUID 表还不随实体死亡清理；而且它兜的不是这条路径。
- 仍然成立的定式：给第三方方向向量先走 `BossPhotoProjHelper.safeDir(to, from, fallback, tag)`
  （长度 <1e-3 或含 NaN/Inf → 退视线方向，再不行 `(0,0,1)`，退化打 `[PhotoBoss] … 方向退化`），
  已覆盖审判（geburah）法阵、骷髅三连箭、回声之星。注意 `Vec3.normalize()` 对**零长度**有防
  （`< 1e-4 → ZERO`），只有 **NaN 输入**才产出 NaN，所以「方向退化」在 `normalize` 这一层本来不会产生 NaN。
- 位移类算式自查口径：**除数必须是长度，不是长度的平方**。地震践踏的 `e.push(dx / d2 …)` 曾把
  平方距离当单位方向用（下限夹 0.001 ⇒ 贴脸推 1000 格/tick），1.8.105 改成先 `sqrt` 再夹。
- 救援：NaN 实体在存档载入时被原版丢弃（`Exception loading entity: Entity has invalid position`），重启即可，不用手动清。

## 第三方弹幕的伤害归属

照片里借第三方实体的效果，伤害分两类：

- **我们自己结算**（`hurt(caster.damageSources().playerAttack(caster), 面板)`）：巨剑竖劈
  （`runSwordCleaves`）、动能力场（`KINETIC_FIELDS`）等 —— 吃主手面板、归属玩家。
- **第三方在自己代码里结算**：目前只有审判（fdbosses `GeburahRayCastingCircle.cast()`）。它用的是
  `BossUtil.transformDamage(level, BOSS_CONFIG.geburahConfig.judgementBirdDamage)`（javap 核对），
  **与玩家面板无关** ⇒ 实测就是「弹幕打出模组原伤害」。
- 1.8.107 起法阵落点与朝向：落在**玩家面朝方向前 2.5 格**（那里是实心方块则退到 1.5 格），方向锁到
  目标**包围盒中心**；<b>锁不到生物就不发</b>（旧版落点在敌人身上、方向按视线外推，命中靠运气）。
  目标优先取「刚打中的那个」，否则半径 `20 − 3.5` 格内最近的敌人（`AllyFilter.isEnemyOf` 口径）。
- 1.8.106 起接管伤害：`spawnGeburahRay` 记下这条射线 {level, origin, dir, 到期 tick, 面板}
  （`GEBURAH_RAYS`，TTL **16 tick**，`onServerTick` 过期清理），`onIncomingDamage` 对
  `fdbosses:geburah_laser_strike` 且落在管线 3 格内的命中把 `amount` 改写成玩家面板。
  **TTL 不能拍脑袋**：`GeburahCastingCircle.tick()` 是 `tickCount == getDuration()/2` 才 `cast()`，
  而 `setCastDuration(d)` 的字节码是 `DURATION = 20 + d` —— `summon()` 传 0 ⇒ duration 20 ⇒
  **第 10 tick 才发射**（第一版按 4 tick 设，整条分支一次都没命中）。
  该伤害类型**不在** `bypasses_armor` / `bypasses_enchantments` 标签里，所以 Incoming 阶段改
  amount 与 `hurt(playerAttack, 面板)` 的护甲/附魔口径一致。几何+时间窗的判定同时把「真·格布拉
  BOSS 自己放的同类法阵」排除在外。归属仍是 fdbosses 的伤害源（击杀归属/元素加成不算玩家）。

## 诅咒近期口径（1.8.90–1.8.101）

- **世界天数**存 `feather/WorldDayData`（附件 + `copyOnDeath`），不再用 `persistentData`——复活只重建实体，
  根上的键会丢（症状：地图还是第 N 天、诅咒天数归零）。老存档按 `lensouls:world_day_start` 一次性折半迁移，日志 `[WorldDays]`。
- **扭曲值单刻度 0–100**：`MAX_TWIST=100`，②与④共用一份存储，HUD/判定同一个数；旧存档折半迁移（`[AbyssTwist]`）。
  受击获取 **0.5/点伤害**。
- **② 满值死亡「只要槽满就爆」**：死亡瞬间扭曲槽满就爆物品并尝试生成扭曲者，**没有**「只罚一次」的标记
  （1.8.100 加过 `lensouls:twist_punished`，导致重生后第二次死亡静默不爆，1.8.102 已整条删除）。
  单戴②时扭曲值死亡不清零，所以重生后槽仍满、再死照旧爆。`BYPASSES_INVULNERABILITY` 来源（`/kill`、虚空）不计受击涨值。
- **取景中不抽手**：`CurseHandDrop.dropHeld` 在 `player.isUsingItem()` 或「主手相机 `CameraItem.isActive`」时跳过
  （抽走正在取景的相机会让客户端卡第三人称、无法用物品、退不出视角）。

## 死亡激光（先驱者）的角度链

- 实体 `Death_Laser_Beam_Entity` 有三套角度，**必须一起看**（实机 3.33 `javap` 核实）：
  - 判定：服务端 `calculateEndPos()` 用同步字段 `getYaw()/getPitch()`；玩家当施法者时不会被
    `updateWithHarbinger()` 刷新（那个方法只认 BOSS 施法者，内容是 `setYaw/setPitch/setPos`）；
  - 客户端几何：`calculateEndPos()` 用 **`renderYaw/renderPitch`**（同一方法按 `isClientSide` 分叉），
    这两个字段在 `tick()` 开头被 `caster.yHeadRot / getXRot()` 刷新，两端都跑；
  - 面片滚转：`renderBeam` 里两处 `Quaternionf.rotationY` 用的是 **`Camera.getXRot()`（相机俯仰）**，
    不是激光自己的角度；第 1 处漏乘 `0.017453292`（把角度当弧度，90 rad ≈ 5156°），第 2 处乘对了；
    两处都包在 `if (!clearerView)` 里 —— 第一人称且施法者是本机玩家时整段被跳过。
- **所以「事后改结果」会错位**：只在 `tick()` 末尾覆盖 `renderYaw/renderPitch`，面片用新角度、
  而末端/命中点/原生闪电仍按头部算 ⇒ 实测「一根对不上末端的柱子 + 一道旁边的闪电」。
  正确做法见 `mixin/compat/CataclysmDeathLaserRenderAimMixin`：在 `tick()` 里**替换角度来源**
  （`caster.yHeadRot` 读取 → `getYaw()*180/π − 90`；`getXRot()` 调用 → `−getPitch()*180/π`），
  下游全部按锁定角计算，贴图/面片/闪电一行不改。
- **不要再用 `DeathLaserCrossRenderMixin` 那套**（改滚转角成 ±45°、强制 `clearerView=false`、
  改爆点帧号）：那是「非原生风格」的来源，1.8.118 已删除。
- 锁敌口径：光柱只在**敌人**之间切换（目标死了→半径内最近的敌人），**永远不回退到施法者视线**
  （面板高时目标常在第一个结算 tick 就被秒，回退会让光柱「闪一下再被拽回准星」）；
  切换是**角度限速**的：持有单位朝向，每 tick 最多转 8°（`DEATH_LASER_TURN_STEP`）。
- 别再往实体 `persistentData` 里找标记：它**不随实体同步到客户端**，客户端读不到。
  途中扫到谁就结算谁 —— 直接 `setYaw(新角度)` 会「一下闪过去」。
